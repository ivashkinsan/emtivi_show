# Архитектура макета TV-экрана

Этот документ описывает финальную архитектуру и принципы работы слоев для компонента "телевизора" в приложении. Цель — создать сложный макет с фиксированной рамкой, фиксированными внутренними хедером и футером, и прокручиваемой центральной частью с контентом.

## 1. Иерархия компонентов (Структура JSX)

Логическая структура рендеринга выглядит следующим образом, начиная с `App.tsx`:

```jsx
// App.tsx
<TVShell>
    <ChannelHeader />
    <div className="channelContainer">
        <div className="channelContent">
            <ChannelPage />
        </div>
    </div>
    <BottomNavigation />
</TVShell>
```

-   **`TVShell`**: Основной компонент-обертка, который создает фон (`AmbientBackground`, `NoiseLayer`) и тело телевизора (`.frame`, `.bezel`, `.screen`).
-   **`ChannelHeader`**: Хедер экрана. Является прямым дочерним элементом "экрана".
-   **`channelContainer`**: Центральная область, которая отвечает за прокрутку контента.
-   **`channelContent`**: Внутренний контейнер, отвечающий за анимацию появления/исчезновения каналов.
-   **`BottomNavigation`**: Футер экрана. Является прямым дочерним элементом "экрана".

## 2. CSS-стратегия и решение проблем

Ключевая логика реализована с помощью **Flexbox** и правильного управления контекстами наложения (`z-index`).

### 2.1. Основной контейнер (`.screen`)

-   `div.screen` внутри `TVShell` является главным контейнером для всего, что мы видим "на экране".
-   Ему заданы `display: flex` и `flex-direction: column`. Это располагает его дочерние элементы (хедер, контент, футер) вертикально, друг под другом.

### 2.2. Фиксированный Header и Footer

-   `ChannelHeader` и `BottomNavigation` являются статичными элементами этого flex-контейнера. Они не используют `position: absolute` или `fixed`.
-   Они не прокручиваются, потому что они не находятся внутри прокручиваемой области.

### 2.3. Прокручиваемый контент

-   Центральный элемент, `div.channelContainer`, является зоной прокрутки.
-   Ему заданы два ключевых свойства:
    1.  `flex: 1`: Это заставляет его растягиваться и занимать все доступное пространство между хедером и футером.
    2.  `overflow-y: auto`: Это включает вертикальную прокрутку, если контент внутри (`.channelContent`) становится выше, чем доступное пространство.

### 2.4. Решение проблемы с "невидимым слоем" (Ключевой фикс)

В процессе разработки возникла проблема, когда контент не реагировал на клики и прокрутку. **Причиной была внутренняя тень `box-shadow: inset` на элементе `.bezel`** (рамка телевизора).

-   По умолчанию, `inset` тень рендерится *поверх* дочерних элементов, создавая невидимый слой, который блокирует все события мыши.
-   **Решение:**
    1.  Родительскому элементу `.bezel` было добавлено `position: relative`, чтобы создать для него свой собственный контекст наложения.
    2.  Дочернему элементу `.screen` были добавлены `position: relative` и `z-index: 1`.

Это "поднимает" весь экран (вместе с хедером, контентом и футером) на один слой выше тени его родителя `.bezel`, делая контент снова доступным для взаимодействия.

```css
/* TVShell.module.css */
.bezel {
    position: relative; /* Создает контекст наложения */
    /* ... box-shadow: inset ... */
}

.screen {
    position: relative;
    z-index: 1; /* Поднимает экран над тенью родителя */
    /* ... display: flex ... */
}
```

Эта архитектура является надежной и решает все поставленные задачи.
